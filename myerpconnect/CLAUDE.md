## 1. ภาพรวมโปรเจกต์ (Project Overview)

- **ชื่อเว็บ:** truman.co.th
- **ประเภท:** เว็บขายอะไหล่มอเตอร์ไซค์ (motorcycle parts e-commerce)
- **ขนาด catalog:** ประมาณ 10,000 SKU
- **แพลตฟอร์ม:** PrestaShop 8 (PHP 8.1+, MariaDB, Smarty template)
- **เจ้าของระบบ/ผู้เช่าแพลตฟอร์ม:** geargaopro.com (ดูข้อ 13 เรื่องสิทธิ์ดูรายงาน)
- **ที่มาของสต็อก:** ดึงจาก ERP เป็นหลัก + ช่องทางขายอื่น (Shopee, Lazada, TikTok Shop)

### Hosting / Infrastructure
- **Server:** VPS ในไทย (Intel Xeon 2 Core, RAM 4GB, SSD 100GB)
- **Control panel:** DirectAdmin (port 2222)
- **ข้อจำกัด:** RAM 4GB ค่อนข้างตึงสำหรับ 10k SKU → ต้องเปิด cache (Redis/Memcached), ตั้ง PHP `memory_limit` อย่างน้อย 512M, และวางแผนอัป RAM เมื่อ traffic โต
- **แนะนำ:** ต่อ Cloudflare (ฟรี) เป็น CDN หน้าบ้าน

## 2. หลักการพัฒนา (Development Principles)

1. **ทำได้ทำ ทำไม่ได้หาทางรองรับให้ดีที่สุด** — ถ้าฟีเจอร์ใดทำตรงๆ ไม่ได้ ให้เสนอทางเลือกที่ใกล้เคียงที่สุด พร้อมอธิบายข้อจำกัด
2. **ใช้ของ PrestaShop ก่อนเขียนใหม่** — ฟีเจอร์หลายอย่าง (หมวดหมู่ รีวิว สมาชิก ตะกร้า) PrestaShop มีอยู่แล้ว ให้ใช้/ปรับแต่งก่อนเขียนโมดูลใหม่
3. **เก็บงานเป็นโมดูล** — โค้ดที่เพิ่มเองให้ทำเป็น PrestaShop module แยก ไม่แก้ core โดยตรง
4. **Responsive ทุกอุปกรณ์** — ต้องใช้งานได้ดีบน Desktop, มือถือ iOS, และ Android
5. **คำนึงถึง performance** — catalog ใหญ่ ต้อง optimize query, ใช้ cache, lazy-load รูป
6. **ความปลอดภัย** — validate input ทุกจุด, escape ใน Smarty (กัน XSS), ป้องกัน SQL injection, เก็บไฟล์เอกสารยืนยันตัวตนอย่างปลอดภัย

## 3. ความต้องการระบบ (Functional Requirements)

### 3.1 การจัดการสินค้าและหมวดหมู่
- เพิ่ม **หมวดหมู่สินค้า** ได้ไม่จำกัด (ตลอดเวลา)
- เพิ่ม/กำหนด **แบนเนอร์** ต่อหมวดหมู่ได้
- เพิ่ม/กำหนด **ป้ายกำกับ (label/tag)** ให้สินค้าได้
- สินค้าหนึ่งตัวลงรูปได้ **สูงสุด 8 รูป**
- ระบบ **ตรวจสอบรูป** อัตโนมัติ: ตรวจขนาด/ฟอร์แมต, **ปรับขนาดรูป** (resize) ให้เป็นมาตรฐาน, **ปรับแต่งสี/คุณภาพรูป** ให้ดูสวยและสม่ำเสมอ
- สินค้าสามารถ **จับคู่เป็นชุด (bundle/combo)** ได้ — เลือกหลายตัวมารวมขายเป็นชุด

### 3.2 รีวิวสินค้า
- ลูกค้า **เขียนรีวิว** สินค้าได้
- Admin **ลบรีวิว** ที่ไม่เหมาะสมได้

### 3.3 ระบบราคาแบบหลายระดับ (Multi-tier Pricing) — สำคัญมาก
ราคาสินค้าแสดงต่างกันตาม **กลุ่มลูกค้า** โดย Admin กำหนดราคาขาย/ส่วนลดเองได้ทุกระดับ:

| กลุ่มลูกค้า | เห็นราคา | หมายเหตุ |
|-----------|---------|---------|
| ลูกค้าทั่วไป (ซื้อใช้เอง) | ราคาปลีก | สมัครด้วยชื่อ ไม่ต้องมีหลักฐาน |
| ช่างซ่อม | ราคาช่าง (ส่งช่าง) | ต้องส่งเอกสารยืนยัน |
| ร้านขายอะไหล่ | ราคาส่ง / เห็นราคาทั้งหมด | ต้องส่งเอกสารยืนยัน |

- **ลำดับการเห็นราคา:** ลูกค้าทั่วไปเห็นราคาปลีก → ช่างเห็นราคาช่าง → ร้านอะไหล่เห็นราคาส่งทั้งหมด
- ลูกค้าทั่วไปเห็นว่าสินค้าตัวนี้ **เปิดทำ affiliate ได้** หรือไม่
- Admin **กำหนดราคาและส่วนลดเอง** ได้ทุกกลุ่ม

### 3.4 ระบบสมาชิก (Membership)
- **สมัครง่าย:** ใช้ `ชื่อ + อีเมล` หรือ `ชื่อ + เบอร์โทร` สมัครได้เลย
- **ยืนยันตัวตน:** ระบบส่งข้อความ (อีเมล/SMS) ให้ลูกค้ากดยืนยัน → เมื่อยืนยันกลับมาแล้วจึงอนุมัติเป็นสมาชิก
- **เลือกกลุ่มเอง:** ตอนสมัคร ลูกค้าเลือกได้ว่าตัวเองเป็นกลุ่มไหน (ซื้อใช้เอง / ช่างซ่อม / ร้านอะไหล่)
- **สมัครก่อนเลือกซื้อ:** ต้องสมัครสมาชิกก่อนจึงเลือกซื้อสินค้าได้

#### เอกสารยืนยันตัวตน (สำหรับช่างซ่อม + ร้านอะไหล่)
ต้องส่งเอกสารให้ Admin อนุมัติก่อนได้สิทธิ์ราคาพิเศษ:
1. รูปถ่ายหน้าร้าน 1 รูป
2. ทะเบียนการค้า / หนังสือรับรอง
3. บัตรประชาชน

### 3.5 ระบบ Affiliate
- ลูกค้าทุกคน (รวมลูกค้าทั่วไป) สมัครทำ affiliate ได้
- **สมัครสมาชิกธรรมดา:** ไม่ต้องใช้หลักฐาน
- **สมัคร affiliate:** ต้องส่งหลักฐาน
  1. บัตรประชาชน
  2. หน้าสมุดบัญชีธนาคาร
  - **เงื่อนไข:** ชื่อในบัตร และ ชื่อบัญชีธนาคาร ต้องตรงกัน
- Admin **กำหนดค่าคอมมิชชั่นเป็น %** ได้
- มี **Dashboard สรุปให้ affiliate ดู** อย่างละเอียด ตามมาตรฐานระบบ affiliate (ยอดคลิก, ยอดขาย, คอมมิชชั่นที่ได้, สถานะการจ่าย ฯลฯ)
- ลูกค้าทั่วไปสามารถ **ดึงสินค้ามาทำ affiliate** ได้: สร้างรูป/วิดีโอโปรโมท (วิดีโอยาวไม่เกิน 2.5 นาที)

### 3.6 ฟีดสินค้าสไตล์ TikTok (Social Commerce Feed)
- หน้าแสดงสินค้าแบบ **เลื่อนดูคล้าย TikTok** (feed วิดีโอ/รูปสินค้า) บนมือถือ iOS/Android
- Admin เป็นคนกำหนดสินค้าที่ขึ้นโชว์ในฟีด
- **หมายเหตุทางกฎหมาย:** ทำให้ "คล้าย" TikTok ได้ แต่ **ห้ามลอกเลียน UI/แบรนด์ของ TikTok ตรงๆ** เพื่อเลี่ยงปัญหาลิขสิทธิ์ ให้ออกแบบสไตล์ของเราเอง
- ลูกค้า **ดึงสินค้าหลายตัวจากฟีดมาใส่ตะกร้า** ได้พร้อมกัน

### 3.7 การนำเข้า/ส่งออกสินค้า (Import / Sync)
- นำเข้าสินค้าจากไฟล์ **Excel** ได้
- ดึง/ซิงค์สินค้าจาก **ERP, Shopee, Lazada, TikTok Shop** ได้
- ERP เป็น "เจ้าของสต็อกตัวจริง" — เว็บ cache สต็อกมา ไม่เก็บถาวรเอง (sync เป็นรอบผ่าน cron)

### 3.8 รายงานและสรุปยอดขาย (Reports & Analytics)
- ระบบสรุปยอดขายตามมาตรฐาน e-commerce
- **สรุปยอดขายแยกตามช่องทาง** (เว็บ, Shopee, Lazada, TikTok)
- **สิทธิ์การดูรายงาน:** เฉพาะ **Admin** และ **geargaopro.com** (ผู้ให้เช่าแพลตฟอร์ม) เท่านั้น
  - geargaopro.com มี password เข้าดูรายงานได้ (read-only หรือ role แยก)
  - ส่งสรุปยอดขายให้ทั้งสองฝ่าย

### 3.9 รองรับทุกอุปกรณ์
- ใช้งานได้บน: **Desktop (คอม), มือถือ iOS, มือถือ Android**
- เป็น responsive web (ถ้าทำ native app ในอนาคต ให้ออกแบบ API รองรับไว้)

## 4. เทคนิคการตลาด/โฆษณาที่ต้องการ (ทำได้จริง ถูกกฎหมาย)

ระบบควรรองรับเทคนิคเพิ่มยอดขายเหล่านี้ (ไม่ใช่ "ดักฟัง" — ใช้ข้อมูลพฤติกรรมจริง):

1. **Behavioral tracking** — เก็บว่าลูกค้าดูสินค้าตัวไหน ค้างนานแค่ไหน เพิ่มอะไรลงตะกร้า
2. **Retargeting** — ติดตั้ง Facebook Pixel / Google Tag เพื่อยิงโฆษณาตามลูกค้า
3. **Recommendation engine** — "คนที่ซื้อ X มักซื้อ Y" แนะนำสินค้าที่มักซื้อคู่กัน (เหมาะกับอะไหล่ที่ใช้คู่กัน)
4. **Email/SMS remarketing** — ลูกค้าทิ้งตะกร้า → ส่งเตือน + ส่วนลด

## 6. ข้อควรระวัง (Constraints & Notes)

- **อย่าแก้ PrestaShop core** — ทำทุกอย่างผ่าน module/override
- **อย่าเก็บข้อมูลล็อกอินหรือ API key ใน code** — ใช้ Configuration ของ PrestaShop หรือ environment variable
- **เอกสารยืนยันตัวตน (บัตร ปชช., สมุดบัญชี)** = ข้อมูลอ่อนไหว → เก็บนอก public folder, จำกัดสิทธิ์เข้าถึง, เข้ารหัสถ้าทำได้
- **ฟีด "คล้าย TikTok"** ต้องไม่ลอก UI/โลโก้/แบรนด์จริง
- **วิดีโอ affiliate** จำกัดความยาว 2.5 นาที + จำกัดขนาดไฟล์เพื่อไม่ให้ storage เต็ม (SSD 100GB)
- ทุกการกระทำสำคัญ (sync, อนุมัติสมาชิก, จ่ายคอมมิชชั่น) ควรมี **log** ไว้ตรวจสอบ

5. โครงสร้างค่าคอมมิชชั่น affiliate: **rate = 1%** ✅ / จ่ายเมื่อไหร่ ❓ / ขั้นต่ำเท่าไหร่ ❓
